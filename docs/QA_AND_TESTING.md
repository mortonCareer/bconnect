# QA & 테스팅

Morton 프로젝트의 QA 및 테스팅 가이드입니다.

---

## QA 플로우 (PR 프리뷰 기반)

```
FE 연동 완료 + PR 생성
    ↓
Vercel 프리뷰 자동 배포 (1-2분)
    ↓
디자이너: UI 검수
  └─ 시안 대비 확인
  └─ 반응형 동작 확인
  └─ 폰트/컬러/간격 확인
    ↓
CTO: 수정 + 기능 테스트
  └─ UI 피드백 반영
  └─ 기능 동작 확인
  └─ 에러 케이스 테스트
    ↓
CEO: 최종 QA
  └─ 실사용자 관점 검증
  └─ 비즈니스 로직 확인
  └─ 엣지 케이스 테스트
    ↓
수정 필요 시: 피드백 반영 → 재검수
    ↓
승인 (Approve)
    ↓
main 머지 → 프로덕션 배포
```

## 테스트 범위

모든 기능은 다음 항목을 테스트해야 합니다:

| 항목        | 내용                         |
| ----------- | ---------------------------- |
| Happy Path  | 정상 흐름 동작 확인          |
| Empty State | 데이터 없을 때 화면 처리     |
| 로딩 상태   | 스피너/스켈레톤 노출         |
| 에러 처리   | 400, 401, 403, 404, 500 대응 |

### 1. Happy Path (정상 흐름)

**목적**: 사용자가 의도한 대로 기능이 동작하는지 확인

**예시 - 프로필 업로드:**

```
1. 프로필 페이지 접속
2. "사진 업로드" 버튼 클릭
3. 이미지 파일 선택
4. 미리보기 표시 확인
5. "저장" 버튼 클릭
6. 성공 메시지 표시
7. 프로필 이미지 업데이트 확인
```

### 2. Empty State (데이터 없음)

**목적**: 데이터가 없을 때 적절한 안내 표시

**예시:**

- 채용 공고 목록이 비었을 때
  - ✅ "등록된 공고가 없습니다" 메시지
  - ✅ "공고 등록하기" 버튼
  - ❌ 빈 화면 또는 로딩 중 표시

- 알림이 없을 때
  - ✅ "새로운 알림이 없습니다" 아이콘 + 텍스트
  - ❌ 빈 목록만 표시

### 3. 로딩 상태

**목적**: 데이터 로딩 중임을 사용자에게 알림

**구현 방법:**

- **스피너**: 버튼 클릭 등 짧은 대기 (1-2초)
- **스켈레톤**: 리스트, 카드 등 긴 로딩 (2초 이상)

**예시:**

```typescript
// 스피너 (버튼)
<Button disabled={isPending}>
  {isPending ? <Spinner /> : '저장'}
</Button>

// 스켈레톤 (리스트)
{isLoading ? (
  <Skeleton count={5} />
) : (
  <UserList data={data} />
)}
```

### 4. 에러 처리

**목적**: 에러 발생 시 사용자가 다음 행동을 할 수 있도록 안내

**상태 코드별 처리:**

| 상태 코드 | 의미        | 화면 처리 예시                            |
| --------- | ----------- | ----------------------------------------- |
| 400       | 잘못된 요청 | "입력값을 확인해주세요"                   |
| 401       | 인증 만료   | 로그인 페이지로 자동 이동                 |
| 403       | 권한 없음   | "접근 권한이 없습니다"                    |
| 404       | 리소스 없음 | "데이터를 찾을 수 없습니다"               |
| 500       | 서버 오류   | "잠시 후 다시 시도해주세요" + 재시도 버튼 |

**에러 메시지 가이드:**

- ✅ 구체적이고 실행 가능한 안내
  - "이메일 형식이 올바르지 않습니다"
  - "파일 크기는 5MB 이하만 가능합니다"

- ❌ 기술적이거나 모호한 메시지
  - "Error: validation failed"
  - "오류가 발생했습니다"

**에러 처리 예시:**

```typescript
function UploadProfile() {
  const { mutate, isPending, error } = useUploadProfileMutation()

  const handleSubmit = (file: File) => {
    mutate(
      { file },
      {
        onError: (error) => {
          if (error.code === 'FILE_TOO_LARGE') {
            toast.error('파일 크기는 5MB 이하만 가능합니다')
          } else if (error.code === 'INVALID_FILE_TYPE') {
            toast.error('JPG, PNG 파일만 업로드 가능합니다')
          } else {
            toast.error('업로드에 실패했습니다. 다시 시도해주세요')
          }
        },
      }
    )
  }

  return (
    <div>
      <FileInput onChange={handleSubmit} disabled={isPending} />
      {error && <ErrorMessage error={error} retry={handleSubmit} />}
    </div>
  )
}
```

## 버그 판단 기준

QA 중 발견된 문제는 다음 기준으로 분류합니다:

| 증상                           | 레이블            | 담당      | 예시                                   |
| ------------------------------ | ----------------- | --------- | -------------------------------------- |
| 스펙 자체가 부족/잘못됨        | `🐛 bug:api-spec` | 둘이 논의 | 필요한 필드가 API 응답에 없음          |
| 응답이 스펙과 다름             | `🐛 bug:BE`       | CEO       | `name` 필드가 null인데 스펙은 required |
| 스펙대로 왔는데 화면 처리 안됨 | `🐛 bug:FE`       | CTO       | 에러 응답이 왔는데 에러 메시지 미표시  |

### 예시 시나리오

**문제**: 사용자 프로필 조회 시 전화번호가 표시되지 않음

**원인 분석:**

1. **API 스펙 확인**
   - OpenAPI 스펙에 `phone` 필드가 정의되어 있는가?
   - ❌ 없음 → `🐛 bug:api-spec` (스펙 추가 필요)
   - ✅ 있음 → 2번으로

2. **API 응답 확인** (개발자 도구 Network 탭)
   - 실제 응답에 `phone` 필드가 포함되어 있는가?
   - ❌ 없거나 null → `🐛 bug:BE` (백엔드 수정)
   - ✅ 있음 → 3번으로

3. **프론트엔드 렌더링 확인**
   - 화면에 전화번호가 표시되지 않음
   - → `🐛 bug:FE` (프론트엔드 수정)

### 버그 이슈 생성

```markdown
## 문제

사용자 프로필 조회 시 전화번호가 표시되지 않음

## 재현 방법

1. 로그인
2. 프로필 페이지 접속
3. 전화번호 필드 확인 → 비어있음

## 예상 동작

전화번호가 표시되어야 함

## 실제 동작

전화번호 필드가 비어있음

## 환경

- URL: https://morton-career-git-feat-123-<team>.vercel.app/profile
- 브라우저: Chrome 120
- 디바이스: iPhone 15 Pro

## 스크린샷

[첨부]

## 레이블

🐛 bug:FE, 💻 FE
```

## 테스트 환경

### 데스크톱

- **브라우저**: Chrome (최신 버전)
- **해상도**: 1920x1080 기준
- **확인 사항**:
  - 레이아웃 깨짐 없음
  - 호버 상태 동작
  - 키보드 네비게이션

### 모바일

- **디바이스**: 본인 기기
- **확인 사항**:
  - 터치 인터랙션
  - 가로/세로 모드 전환
  - 소프트 키보드 표시 시 레이아웃
  - iOS/Android 차이점

### 반응형 테스트

프리뷰 환경에서 다음 해상도 확인:

| 디바이스    | 해상도    |
| ----------- | --------- |
| Mobile (S)  | 375x667   |
| Mobile (L)  | 414x896   |
| Tablet      | 768x1024  |
| Desktop (S) | 1366x768  |
| Desktop (L) | 1920x1080 |

**Chrome DevTools:**

1. F12 → Toggle device toolbar
2. 각 해상도로 전환하며 테스트
3. 레이아웃 깨짐, 잘림, 스크롤 이슈 확인

## 자동화 vs 수동 테스트

### 자동화 테스트 (Backend만)

현재 Backend에만 자동화 테스트가 구성되어 있습니다.

**실행 명령어:**

```bash
cd apps/api
./gradlew test              # 전체 테스트
./gradlew test --tests ClassName  # 특정 클래스
```

**테스트 범위:**

- Unit Tests (Service, Repository)
- Integration Tests (API 엔드포인트)
- 데이터 검증 로직

### 수동 테스트 (Frontend)

Frontend는 현재 수동 QA로 진행합니다.

**PR 프리뷰 환경에서 수동 테스트:**

1. Vercel 프리뷰 URL 접속
2. 테스트 범위 항목 체크 (Happy Path, Empty State, 로딩, 에러)
3. 데스크톱/모바일 환경 테스트
4. 이슈 발견 시 GitHub Issue 생성

**향후 계획:**

- Vitest + React Testing Library 도입 예정
- E2E 테스트 (Playwright) 검토 중

## QA 체크리스트

PR 생성 시 다음 체크리스트를 확인합니다:

### 기능 동작

- [ ] Happy Path 정상 동작
- [ ] Empty State 적절히 표시
- [ ] 로딩 상태 표시 (스피너/스켈레톤)
- [ ] 에러 처리 (400, 401, 403, 404, 500)

### UI/UX

- [ ] Figma 시안 대비 일치
- [ ] 반응형 동작 확인 (모바일/태블릿/데스크톱)
- [ ] 버튼/링크 호버 상태
- [ ] 포커스 스타일 (키보드 네비게이션)

### 접근성

- [ ] 버튼/링크에 적절한 텍스트
- [ ] 이미지에 alt 속성
- [ ] 폼 input에 label 연결

### 성능

- [ ] 이미지 최적화 (webp, lazy loading)
- [ ] 불필요한 API 호출 없음
- [ ] 페이지 로딩 시간 3초 이내

### 보안

- [ ] 민감 정보 노출 없음 (콘솔, 네트워크 탭)
- [ ] HTTPS 사용
- [ ] XSS 방어 (사용자 입력 sanitize)

## 문제 해결

### Vercel 프리뷰가 안 뜰 때

1. **Vercel 빌드 로그 확인**
   - GitHub PR 댓글의 "Details" 클릭
   - 빌드 에러 메시지 확인

2. **흔한 원인**
   - TypeScript 타입 에러
   - ESLint 에러
   - 환경 변수 누락
   - 빌드 타임아웃

3. **해결 방법**
   - 로컬에서 `pnpm build` 실행
   - 에러 수정 후 재푸시

### 테스트 데이터 생성

QA 시 필요한 테스트 데이터:

```bash
# Mock API 사용 시
# OTP 인증 코드: 123456 (고정)
phone: +821012345678
code: 123456

# 테스트 계정
CEO: +821012345678 (김철수, 업체)
CTO: +821087654321 (이영희, 기술자)
```

### 프리뷰 환경에서 로그인 안 될 때

- Mock API 서버가 실행 중인지 확인
- 실제 API 사용 시: 백엔드 배포 상태 확인
- 쿠키/로컬스토리지 초기화 후 재시도
