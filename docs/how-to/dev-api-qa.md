# dev 환경 QA 계정 사용법

> **For**: dev 환경(`api.dev.bconnect.to`)에서 기능을 확인하는 모든 사람.
> **You'll be able to**: 확인하려는 내용에 맞는 테스트 계정을 고르고, 문자 없이 로그인하고, 데이터가 언제 사라지는지 예측한다.

---

## 테스트 계정은 두 갈래

dev 데이터베이스에는 미리 만들어 둔 계정이 두 묶음 들어 있습니다. 확인하려는 내용에 따라 골라 쓰면 됩니다.

| 묶음               | 전화번호                                                                                              | 들어 있는 것                                                             | 이럴 때 씁니다                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------- |
| **100번대**        | `01000000002` (테스트·관리자), `01000000003` (반장1), `01000000006`·`007`·`008`·`009`·`011` (반장2~6) | 프로필 정도만. 업체·게시물 없음, 작업도 거의 없음                        | 가입 직후 상태, 아무것도 없을 때 화면이 어떻게 보이는지 |
| **200번대**        | `01000000200`·`204`·`205`·`206`·`207` (업체 5), `01000000201`·`202`·`203`·`208`·`209` (반장 5)        | 업체 5 + 반장 5, 프로젝트 5, 작업 21, 섭외·자격·게시물·동료·드라이브까지 | 목록·상세 조회, 작업 흐름, 데이터가 많을 때의 화면      |
| **아직 없는 번호** | `01000000001` 등                                                                                      | 회원 자체가 없음                                                         | 가입 절차 전체                                          |

작업 상태별로 확인하려면 200번대가 편합니다. 샘플 프로젝트 한 곳에 초안·섭외중·예정·진행중·완료 작업이 하나씩 들어 있습니다.

원본은 [data.sql](../../apps/api/src/main/resources/data.sql)입니다. 어떤 계정에 무엇이 붙어 있는지 정확히 알고 싶으면 이 파일을 봅니다.

---

## 데이터는 배포될 때마다 초기화됩니다

dev 서버는 새로 뜰 때마다 데이터베이스를 통째로 지우고 위 계정들을 다시 넣습니다. `dev` 브랜치에 뭔가 머지되면 배포가 돌고, 그때 초기화가 일어납니다.

그래서:

- **QA 중에 만든 데이터(가입한 계정, 올린 게시물, 만든 작업)는 다음 배포 때 사라집니다.** 남겨야 할 게 있으면 화면을 저장해 두세요.
- 반대로 **계정 상태는 항상 같은 자리에서 시작합니다.** 누가 앞서 망쳐 놓은 데이터 때문에 헷갈릴 일이 없습니다.
- 재현이 필요한 문제는 "배포 직후 상태에서 무엇을 했는지" 순서대로 적어 두면 그대로 다시 만들 수 있습니다.

이 동작은 dev 서버만 그렇습니다. 실서비스(prod)는 초기화하지 않습니다.

## 로그인: 문자 대신 데이터베이스에서 인증번호 꺼내기

dev 서버도 실제로 문자를 보냅니다. 그런데 테스트 계정 번호(`010-0000-...`)는 실제로 존재하지 않는 번호라 문자가 도착하지 않습니다.

대신 **인증번호는 문자를 보내기 전에 이미 데이터베이스에 저장됩니다.** 그래서 문자가 실패해도 데이터베이스를 보면 번호를 알 수 있습니다.

> 개발자에게 "인증번호 좀 불러주세요"라고 요청하지 마세요. 아래 방법으로 직접 꺼내면 됩니다.

### 1) 배포 직후라면 — 고정 번호 4개

배포 직후에는 아래 네 개가 고정된 인증번호를 갖고 있습니다. 이건 그냥 입력하면 됩니다.

| 전화번호      | 인증번호 | 상태                         |
| ------------- | -------- | ---------------------------- |
| `01000000001` | `000001` | 회원 없음 (가입 절차 확인용) |
| `01000000002` | `000002` | 테스트 계정 (관리자)         |
| `01000000003` | `000003` | 반장1                        |
| `01000000004` | `000004` | 가입 중간 단계               |

한 번 쓰면 그 번호는 소진됩니다. 다시 쓰려면 아래 2)번 방법으로 새 번호를 꺼내세요.

### 2) 그 외 모든 계정 — `pnpm otp` 로 꺼내기

최초 한 번만 railway 에 로그인합니다.

```bash
railway login
```

이후로는 이 한 줄이 전부입니다.

1. 앱 로그인 화면에서 원하는 번호를 넣고 인증번호 요청을 누릅니다 (문자는 안 옵니다. 정상입니다)
2. 터미널에서 방금 그 번호를 넣고 실행합니다

   ```bash
   pnpm otp 01000000200
   ```

   ```text
   🔑 199853   (남은 시간 2분 58초)
   ```

3. 나온 번호를 화면에 입력합니다

이 명령은 **조회만 합니다.** 인증번호를 새로 보내지 않으므로, 앱에서 막 요청한 직후에 바로 써도 재전송 제한(60초)에 걸리지 않습니다.

인증번호를 못 쓰는 상태면 이유를 대신 알려줍니다.

| 나오는 말              | 뜻               | 할 일                  |
| ---------------------- | ---------------- | ---------------------- |
| 요청된 인증번호가 없음 | 아직 요청 안 함  | 앱에서 먼저 요청       |
| 만료됐습니다           | 3분 지남         | 앱에서 다시 요청       |
| 이미 사용한 인증번호   | 로그인에 이미 씀 | 앱에서 다시 요청       |
| 5회 틀려서 잠겼습니다  | 5번 잘못 입력함  | 앱에서 재전송하면 풀림 |
