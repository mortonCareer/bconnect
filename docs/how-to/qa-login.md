# QA 로그인법

> 대상: QA 개발자<br>
> 학습 목표: 검증 목적별 로그인 계정을 선택하고 데이터를 활용할 수 있다.

## 테스트 계정은 두 갈래

dev 데이터베이스에는 미리 만들어 둔 계정이 두 묶음 들어 있습니다. 확인하려는 목적에 따라 골라 쓰면 됩니다.

### 테스트 계정

| id   | 전화번호      | 인증번호 | 데이터               | 용도          |
| ---- | ------------- | -------- | -------------------- | ------------- |
| 없음 | `01000000001` | `000001` | -                    | 회원가입      |
| 100  | `01000000002` | `000002` | 동료, 드라이브, 알림 | 시나리오 검증 |

### 샘플 계정

| id  | 전화번호      | 인증번호 | 데이터                                            | 용도 |
| --- | ------------- | -------- | ------------------------------------------------- | ---- |
| 200 | `01000000200` | -        | 업체 · 프로젝트, 동료, 채팅, 드라이브, 알림       | 업체 |
| 201 | `01000000201` | -        | 업체 · 프로젝트, 작업, 동료, 채팅, 드라이브, 알림 | 반장 |

## 데이터는 배포될 때마다 초기화됩니다

dev 서버는 새롭게 배포될 때마다 데이터베이스를 초기화합니다.

그래서:

- QA 중에 만든 데이터(가입한 계정, 올린 게시물, 만든 작업)는 다음 배포 때 사라집니다. 남겨야 할 게 있으면 화면을 저장해 두세요.
- 반대로 계정 상태는 항상 같은 자리에서 시작합니다. 누가 앞서 망쳐 놓은 데이터 때문에 헷갈릴 일이 없습니다.
- 재현이 필요한 문제는 "배포 직후 상태에서 무엇을 했는지" 순서대로 적어 두면 그대로 다시 만들 수 있습니다.

이 동작은 dev 서버만 그렇습니다. 실서비스(prod)는 초기화하지 않습니다.

## 로그인 백도어

배포 직후에는 아래 네 개가 고정된 인증번호를 갖고 있습니다. 이건 그냥 입력하면 됩니다.

| 전화번호      | 인증번호 | 상태                         |
| ------------- | -------- | ---------------------------- |
| `01000000001` | `000001` | 회원 없음 (가입 절차 확인용) |
| `01000000002` | `000002` | 테스트 계정 (관리자)         |
| `01000000003` | `000003` | 반장1                        |
| `01000000004` | `000004` | 가입 중간 단계               |

로그인에 성공하면 그 번호는 더 못 씁니다.

인증번호는 전화번호당 한 개만 저장됩니다. 여럿이 같은 번호를 동시에 쓰면 나중 요청이 앞사람 것을 덮어써서 앞사람이 로그인에 실패하니, 계정을 나눠 쓰세요.
