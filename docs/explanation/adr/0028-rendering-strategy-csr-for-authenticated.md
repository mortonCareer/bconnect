# ADR-0028: 로그인이 필요한 화면은 브라우저에서 그리고, 공개 화면만 서버 렌더링을 검토한다

- **Status**: Proposed
- **Date**: 2026-07-29
- **Deciders**: @manamana32321
- **Related**: [ADR-0027](./0027-role-route-gating-client-component.md)

## Context

[ADR-0027](./0027-role-route-gating-client-component.md) 을 정리하면서, 왜 서버에서 권한을 확인할 수 없는지가 드러났습니다. access token 이 브라우저 JS 메모리에만 있고 refresh token 쿠키는 경로가 좁혀져 있어, Next 서버는 회원이 누구인지 알 방법이 없습니다.

현재 코드가 실제로 어떤 상태인지 확인했습니다.

| 항목 | 수 |
| --- | --- |
| 서버 컴포넌트 | 17 |
| 클라이언트 컴포넌트 | 27 |
| 서버 컴포넌트에서 데이터를 가져오는 곳 | 0 |
| `next/headers` 사용 | 0 |

서버 컴포넌트 17 개는 전부 주소 매개변수를 풀어 클라이언트 컴포넌트를 렌더하는 얇은 껍데기입니다. 로그인이 필요한 데이터는 전부 브라우저에서 가져옵니다.

즉 "로그인이 필요한 화면은 브라우저에서 그린다" 는 이미 사실상의 상태인데, 문서로 적힌 적이 없어 앞으로 서버 렌더링을 늘릴 때 판단 기준이 없습니다.

## Options

### Option 1: 전부 브라우저 렌더링으로 못 박기

- **장점**: 기준이 단순합니다
- **단점**: 공개 페이지에서 얻을 수 있는 첫 화면 속도와 검색 노출을 포기합니다

### Option 2: 서버 렌더링으로 옮기기

토큰을 서버가 읽을 수 있는 쿠키로 옮기고, 서버에서 데이터를 가져옵니다.

- **장점**: 첫 화면이 빨라지고 권한 확인도 서버에서 할 수 있습니다
- **단점**: 토큰 보관 방식을 바꾸는 일이라 XSS·CSRF 대비를 통째로 다시 설계해야 합니다
- **단점**: 부분 도입이 되지 않습니다. 지금 겪는 성능 문제가 없는데 위험만 큽니다

### Option 3: 로그인 필요 여부로 선을 긋기

로그인이 필요한 화면은 브라우저에서 그리고, 공개 화면만 서버 렌더링을 검토합니다.

- **장점**: 공개 화면은 토큰이 필요 없어 **지금 구조 그대로** 서버에서 가져올 수 있습니다
- **장점**: 토큰 보관 방식을 건드리지 않습니다
- **단점**: 두 방식이 한 앱에 공존해 어느 쪽인지 헷갈릴 수 있습니다. 그래서 기준을 문서로 둡니다

## Decision

**Option 3 을 택합니다.**

- **로그인이 필요한 화면**: 브라우저에서 그립니다. 서버가 세션을 볼 수 없어 다른 선택지가 없고, 이 화면들은 로그인 후에만 보이므로 첫 화면 속도의 중요도가 상대적으로 낮습니다
- **공개 화면**: 서버 렌더링 후보입니다. 다만 지금 당장 옮기지는 않습니다

당장 옮기지 않는 이유는 성능 문제가 아직 없기 때문입니다. 이 ADR 은 문제가 생겼을 때의 판단 기준을 미리 정해두는 것이고, 그래서 Status 를 Proposed 로 둡니다.

옮기기 전에 반드시 병목을 먼저 측정합니다. 느림의 원인이 서버 렌더링 부재가 아니라 API 응답 시간이거나 mock 지연 설정일 수 있고, 그 경우 옮겨도 그대로입니다.

career 는 앱으로 감싸 배포하므로 검색 노출 이득이 없습니다. 실질 후보는 plan 의 공개 목록입니다. 회사 홈페이지는 이미 별도 앱으로 분리되어 있습니다.

## Consequences

- **좋은 결과**: 새 화면을 만들 때 어느 방식으로 할지 판단 기준이 생깁니다
- **좋은 결과**: 토큰 보관 방식을 건드리지 않아 보안 설계를 다시 하지 않아도 됩니다
- **나쁜 결과**: 로그인이 필요한 화면의 첫 진입은 계속 왕복이 필요합니다
- **중립적 결과**: 한 앱에 두 방식이 공존합니다

## Notes

Status 를 Accepted 로 올리는 시점은, 공개 화면에서 실제로 느림이 측정되고 그 원인이 렌더링 방식으로 확인될 때입니다.

인증 구조를 바꿔 서버가 세션을 볼 수 있게 하는 선택은 이 ADR 이 다루지 않습니다. 그때는 [ADR-0027](./0027-role-route-gating-client-component.md) 과 함께 새 ADR 로 다시 씁니다.
