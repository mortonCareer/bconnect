# ADR-0021: OTP 발송

- 상태: 승인됨
- 날짜: 2026-06-10
- 담당자: @manamana32321, @fine-pine

## 개요

OTP 메시지를 어떤 채널·어떤 사업자로 보낼지 정해야 한다. BConnect 는 휴대폰 OTP 로 로그인·회원가입을 인증한다. 인증 흐름은 Phone OTP → tokens 다.

결정의 무게를 키우는 force 두 가지:

- 비용 비중: 개발 예산 예측 결과 OTP 발송 단가가 전체의 약 55% 를 차지한다. 단가가 곧 런레이트를 좌우하므로 채널·벤더 선택이 비용에 직접 직결된다.
- 카카오 정책 제약, 검증 완료: 사업자가 자체 서버에서 카카오톡 SDK 로 알림톡을 직접 발송하는 것은 정책상 불가하다. 알림톡은 카카오가 인증한 발송대행사, 즉 중계업체를 반드시 경유해야 한다. 발송은 사전 승인된 템플릿으로만 가능하다. 근거는 [카카오 비즈니스 : 알림톡 발송 예시](https://kakaobusiness.gitbook.io/main/ad/infotalk/send-example) 와 [카카오 고객센터 : 알림톡 발송 자격](https://cs.kakao.com/helps_html/1073208550) 다. 가이드의 "일회용 비밀번호" 예시로 알림톡 OTP 자체는 가능함을 확인했다. SMS 역시 통신사 직결이 아니라 발송대행사를 경유한다.

따라서 "중계업체 경유"는 선택이 아니라 제약이다. 실제 결정 축은 둘이다.

1. 어떤 채널인가. 알림톡 vs SMS
2. 어떤 발송대행사인가

추가 제약은 CEO 가 제시했다. BE 코드가 발송 로직 때문에 지저분해지지 않아야 한다.

## 선택지

### 채널: 알림톡 주채널 + SMS 폴백

- 알림톡은 SMS 대비 단가가 낮다. Solapi 기준 약 25%↓, 뿌리오 기준 약 15%↓. OTP 처럼 짧고 정형화된 메시지엔 알림톡이 적합.

단점

- 발송 문구의 통제권을 일부 잃고 카카오 사전 승인 템플릿 규정에 종속된다.
- 카카오톡 미사용자는 알림톡 수신이 불가하다. 미사용자는 소수지만 존재한다. 따라서 알림톡 실패 시 SMS 로 폴백하는 로직이 필요하다. 알림톡·SMS 를 모두 지원하는 벤더여야 한다.

### 옵션 1: Solapi (채택)

사전 승인 템플릿 기반으로 알림톡·SMS 를 모두 지원한다. 이미 연동되어 동작 중이다.

장점

- 지금 당장 동작. 추가 연동 0
- 알림톡·SMS 단일 벤더라 폴백 구현 용이
- 토큰 수동 갱신 같은 런타임 운영부담 없음

단점

- 단가가 뿌리오보다 높음
- 예산 55% 비중을 고려하면 장기 비용 열위

### 옵션 2: 뿌리오(Ppurio)

알림톡·SMS 를 지원한다. SMS 가 Solapi 대비 약 절반, 알림톡도 약 15% 저렴하다. API 키로 AT 를 발급받고, 그 AT 로 발송한다. AT 는 액세스 토큰이며 발급 후 24시간 만료다. 별도 SDK 는 불필요하다.

장점

- 단가 최저. 예산 55% 비중에서 절감폭 큼
- SDK 의존성 없음

단점

- AT 를 24시간마다 갱신해야 함
- 스프링 프로세스, 즉 컨테이너마다 만료 시점에 재발급 로직이 필요
- 토큰 중복 발급 허용 여부가 불명확해 멀티 인스턴스에서 갱신 경합 처리에 추가 설계가 듦
- 위 두 항목이 "BE 코드 단순성" 제약과 충돌

### 옵션 3: 옥토모(Octomo) 역방향 OTP

사용자가 우리에게 인증 메시지를 보내는 역방향 방식이라 발송 비용이 무료다.

장점

- 비용 0

단점

- 사용자가 메시지를 "받는" 게 아니라 "보내야" 하는 UX 라 기존 OTP 흐름과 이질적
- 회원가입·로그인 UX 를 전면 재설계해야 함

## 결정사항

채널은 알림톡 주채널 + SMS 폴백, 벤더는 당분간 Solapi, 즉 옵션 1 을 채택한다.

우선시한 force 는 즉시성과 운영 단순성이다. Solapi 는 이미 동작 중이다. 알림톡·SMS 폴백을 단일 벤더로 묶을 수 있다. 뿌리오의 AT 24시간 갱신 같은 런타임 운영로직이 없어 "BE 코드 깔끔" 제약에 부합한다.

받아들인 트레이드오프는 단가다. OTP 가 예산의 55% 인 만큼 뿌리오 대비 비용 열위는 실재한다. 다만 사용자 규모가 작은 현 시점에선 절대 비용차가 크지 않고 운영 안정성이 더 중요하다고 판단했다.

뿌리오는 유저 규모가 충분히 커져 단가 절감폭이 운영 복잡도를 정당화할 때 재평가한다. 옥토모 역방향 방식은 UX 변경 부담으로 현 시점 미채택.

## 기대 효과

- 좋은 결과:
  - OTP 발송이 추가 연동 없이 즉시 동작. Solapi 는 기연동 상태
  - 알림톡 주채널로 SMS 대비 발송 단가 절감, SMS 폴백으로 카카오톡 미사용자까지 커버
  - 단일 벤더라 폴백 분기·청구·운영 창구가 하나로 단순
- 나쁜 결과:
  - 메시지 문구가 카카오 사전 승인 템플릿에 종속 → 문구 자유도 하락, 템플릿 변경 시 심사 리드타임 발생
  - 예산 55% 를 차지하는 OTP 단가의 최적화 여지가 미해결로 남음 → 향후 숙제. 뿌리오 등이 후보
- 중립적 결과:
  - 발송 로직을 알림톡/SMS 통합 인터페이스 + 벤더 어댑터로 두면 향후 뿌리오 등으로 교체할 때 호출부 영향이 격리된다. 이 구성은 이송목의 "BE 코드 깔끔" 제약을 반영한다. 어댑터 경계 설계는 구현 시 [#570](https://github.com/mortonCareer/bconnect/issues/570) 에서 다룬다.

## 메모

- 벤더 재평가 트리거: 사용자 규모 확대로 OTP 월 단가가 유의미해지면 뿌리오와 Solapi 를 재비교한다. 뿌리오는 단가 우위, Solapi 는 운영 단순이 강점이다. 어댑터 경계가 있으면 교체 비용은 낮다.
- 알림톡 템플릿: OTP 용 일회용 비밀번호 템플릿을 Solapi 콘솔에서 사전 등록·승인받아 사용한다. [Solapi 카카오 템플릿](https://console.solapi.com/kakao/templates) 참조.
