# ADR-0021: OTP 발송 — 중계업체(Solapi) 경유 + 알림톡 주채널·SMS 폴백

- **Status**: Accepted
- **Date**: 2026-06-10
- **Deciders**: @manamana32321, @fine-pine
- **Related**: [#570](https://github.com/mortonCareer/bconnect/issues/570) (구현 추적), [Solapi 콘솔 — 카카오 템플릿](https://console.solapi.com/kakao/templates), [뿌리오 발송 API 가이드](https://www.ppurio.com/send-api/guide), [카카오 비즈니스 — 알림톡 발송 예시(일회용 비밀번호)](https://kakaobusiness.gitbook.io/main/ad/infotalk/send-example), [카카오 고객센터 — 알림톡 발송 자격](https://cs.kakao.com/helps_html/1073208550)

## Context

BConnect는 휴대폰 OTP 로 로그인·회원가입을 인증한다(Phone OTP → tokens). OTP 메시지를 어떤 채널·어떤 사업자로 보낼지 정해야 한다.

결정의 무게를 키우는 force 두 가지:

- **비용 비중**: 개발 예산 예측 결과 OTP 발송 단가가 전체의 약 **55%** 를 차지한다. 단가가 곧 런레이트를 좌우하므로 채널·벤더 선택이 비용에 직접 직결된다.
- **카카오 정책 제약(검증됨)**: 사업자가 자체 서버에서 카카오톡 SDK 로 알림톡을 **직접 발송하는 것은 정책상 불가**하다. 알림톡은 카카오가 인증한 **발송대행사(중계업체)** 를 반드시 경유해야 하고, 사전 승인된 템플릿으로만 보낼 수 있다. (근거: [카카오 비즈니스 알림톡 가이드](https://kakaobusiness.gitbook.io/main/ad/infotalk/send-example), [고객센터 자격 안내](https://cs.kakao.com/helps_html/1073208550). 가이드의 "일회용 비밀번호" 예시로 알림톡 OTP 자체는 가능함을 확인.) SMS 역시 통신사 직결이 아니라 발송대행사를 경유한다.

따라서 "중계업체 경유"는 선택이 아니라 **제약**이고, 실제 결정 축은 (1) 어떤 채널(알림톡 vs SMS), (2) 어떤 발송대행사다.

추가 제약(CEO): **BE 코드가 발송 로직 때문에 지저분해지지 않아야 한다**.

## Options

### 채널: 알림톡 주채널 + SMS 폴백

- 알림톡은 SMS 대비 단가가 낮다(Solapi 기준 약 25%↓, 뿌리오 기준 약 15%↓). OTP 처럼 짧고 정형화된 메시지엔 알림톡이 적합.
- 단점: 발송 문구의 통제권을 일부 잃고 카카오 사전 승인 템플릿 규정에 종속된다.
- 카카오톡 미사용자(소수지만 존재)는 알림톡 수신이 불가하므로, **알림톡 실패 시 SMS 로 폴백**하는 로직이 필요하다 → 알림톡·SMS 를 모두 지원하는 벤더여야 한다.

### Option 1: Solapi (채택)

사전 승인 템플릿 기반으로 알림톡·SMS 를 모두 지원. 이미 연동되어 동작 중.

- **장점**: 지금 당장 동작(추가 연동 0) · 알림톡+SMS 단일 벤더로 폴백 구현 용이 · 토큰 수동 갱신 같은 런타임 운영부담 없음
- **단점**: 단가가 뿌리오보다 높음(예산 55% 비중을 고려하면 장기 비용 열위)

### Option 2: 뿌리오(Ppurio)

알림톡·SMS 지원. SMS 가 Solapi 대비 약 절반, 알림톡도 약 15% 저렴. API 키 → AT(액세스 토큰, 발급 후 24시간 만료) → 그 AT 로 발송. 별도 SDK 불필요.

- **장점**: 단가 최저(예산 55% 비중에서 절감폭 큼) · SDK 의존성 없음
- **단점**: **AT 를 24시간마다 갱신**해야 함. 스프링 프로세스(컨테이너)마다 만료 시점에 재발급 로직이 필요하고, 토큰 중복 발급 허용 여부가 불명확해 멀티 인스턴스에서 갱신 경합을 어떻게 다룰지 추가 설계가 든다 → "BE 코드 단순성" 제약과 충돌

### Option 3: 옥토모(Octomo) — 역방향 OTP

사용자가 우리에게 인증 메시지를 보내는 역방향 방식이라 발송 비용이 **무료**.

- **장점**: 비용 0
- **단점**: 사용자가 메시지를 "받는" 게 아니라 "보내야" 하는 UX 라 기존 OTP 흐름과 이질적. 회원가입·로그인 UX 를 전면 재설계해야 함

## Decision

**채널은 알림톡 주채널 + SMS 폴백, 벤더는 당분간 Solapi(Option 1)를 채택한다.**

우선시한 force 는 **즉시성과 운영 단순성**이다. Solapi 는 이미 동작 중이고 알림톡·SMS 폴백을 단일 벤더로 묶을 수 있으며, 뿌리오의 AT 24시간 갱신 같은 런타임 운영로직이 없어 "BE 코드 깔끔" 제약에 부합한다. 받아들인 트레이드오프는 **단가**다 — OTP 가 예산의 55% 인 만큼 뿌리오 대비 비용 열위는 실재하지만, 사용자 규모가 작은 현 시점에선 절대 비용차가 크지 않고 운영 안정성이 더 중요하다고 판단했다.

뿌리오는 **유저 규모가 충분히 커져 단가 절감폭이 운영 복잡도를 정당화할 때 재평가**한다. 옥토모 역방향 방식은 UX 변경 부담으로 현 시점 미채택.

## Consequences

- **좋은 결과**:
  - OTP 발송이 추가 연동 없이 즉시 동작(Solapi 기연동)
  - 알림톡 주채널로 SMS 대비 발송 단가 절감, SMS 폴백으로 카카오톡 미사용자까지 커버
  - 단일 벤더라 폴백 분기·청구·운영 창구가 하나로 단순
- **나쁜 결과**:
  - 메시지 문구가 카카오 **사전 승인 템플릿**에 종속 → 문구 자유도 하락, 템플릿 변경 시 심사 리드타임 발생
  - 예산 55% 를 차지하는 OTP 단가의 최적화 여지(뿌리오 등)가 미해결로 남음 → 향후 숙제
- **중립적 결과**:
  - 발송 로직을 **알림톡/SMS 통합 인터페이스 + 벤더 어댑터**로 두면(이송목 "BE 코드 깔끔" 제약 반영), 향후 뿌리오 등으로 교체할 때 호출부 영향이 격리된다. 어댑터 경계 설계는 구현 시 [#570](https://github.com/mortonCareer/bconnect/issues/570) 에서 다룬다.

## Notes

- **벤더 재평가 트리거**: 사용자 규모 확대로 OTP 월 단가가 유의미해지면 뿌리오(단가 우위) vs Solapi(운영 단순) 재비교. 어댑터 경계가 있으면 교체 비용은 낮다.
- **알림톡 템플릿**: OTP 용 일회용 비밀번호 템플릿을 Solapi 콘솔에서 사전 등록·승인받아 사용([템플릿 관리](https://console.solapi.com/kakao/templates)).
- OTP 테스트 번호/코드 운용은 [qa-and-testing.md](../../how-to/qa-and-testing.md) 의 "테스트 데이터 생성" 참조.
