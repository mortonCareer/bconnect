# 가이드라인
- 계획 문서를 작성하지 말고, 전체적인 단계에 따라 사용자와 함께 논의하며 진행하세요.
- 코드 변경사항은 클래스명-인터페이스-구현 순서로 사용자와 논의하며 구체화하세요.
- 코드 변경사항 제안시 REFERENCE.md 및 주요 문서, 그리고 프로젝트 내부 코드를 참고하세요.
- 코드를 실제로 작성하기 전에 사용자에게 코드 변경사항을 제안하고, 승인 받으세요.
- 사용자가 승인한 사항과 AI가 제안한 사항을 명백하게 구분하세요.
- 외부 라이브러리를 활용할 때는 공식 문서를 기반으로 코드를 작성하세요.
- 수정 또는 신규 구현 시, 더 이상 사용되지 레거시 코드를 제거하세요.
- 이전 대화 내용을 바탕으로 체크리스트를 작성 · 관리하세요.
- Git, LSP 명령어 오류가 3회 이상 발생한 경우 해당 Git, LSP 작업을 건너뛰세요.
- 계획이 마무리되었다면, 커밋 메시지를 제안하고 빌드 및 테스트를 수행하세요.
- 커밋 메시지는 Git 명령어 없이 작업 내용을 기반으로 제안하세요.
